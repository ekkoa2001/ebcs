# Ekko Brand Content Strategy — V1 原地升级需求

> 本文档是本项目后续开发的唯一需求基准。必须在当前纯净 V1 上原地迭代，完整实现品牌创意、品牌内容、营销方案、广告数据、竞品洞察与团队管理；不是另起项目、不是静态 Demo，也不是只输出框架。

## 0. 项目位置与升级原则

工作目录：

```text
C:\Users\win\Desktop\Ekko Script Web-团队版
```

现有 V1 是唯一 UI 与交互基线。开发必须遵守：

1. 保留当前顶部导航的高度、排列、按钮尺寸和交互方式。
2. 保留当前蓝白配色、红/绿/蓝状态色和粉色日期强调。
3. 保留当前卡片比例、卡片内容层级、按钮位置和 Hover 效果。
4. 保留当前弹窗、表单、筛选栏、分页、分镜横向展示和广告数据页面视觉。
5. 保留当前登录页和 GSAP 动画，只修复功能或稳定性问题。
6. 新模块必须复用现有 `.nav`、`.card`、`.tab`、`.tools`、`dialog`、`.fields`、`.metric-table`、`.storyboard-scroll` 等组件样式。
7. 禁止改成侧边栏、玻璃拟态、全新模板、大面积渐变或另一套设计语言。
8. 禁止为了迁移到 Vue/Tailwind 重画页面。本轮升级继续使用 V1 原生 HTML、CSS、JavaScript。
9. 可以机械拆分大文件，但拆分前后 DOM、class、布局和视觉必须一致。
10. 架构升级发生在数据库、后端、API、权限、图片存储和 JavaScript 模块化，不发生在 UI 重做。

所谓“不改变 UI”指：不改变视觉体系与核心交互。允许在现有导航样式中调整业务名称、增加必要入口；允许在现有卡片、页签和弹窗结构内增加业务字段。

## 2. 项目目标

将当前 Ekko Script Web 升级为面向市场部门的品牌内容积累、协作、执行和分析系统，统一管理：

- 品牌创意与短视频脚本
- 品牌视觉内容
- 营销方案
- 售后与客户生命周期
- 广告投放数据
- 竞品洞察
- 团队审核、评价与复盘
- 用户、权限、归档和操作审计

最终形成：

```text
创意钩子 → 产品出场 → 完整脚本 → 分镜 → 成品视频 → 投放数据 → 复盘
品牌内容 → 营销方案／生命周期节点 → 渠道执行 → 数据表现 → 复盘
```

## 7. 品牌创意模块

### 7.1 创意钩子

字段：编号、标题、创意内容、钩子类型、产品、人群、场景、参考素材、标签、筛选状态、创建者、负责人、创建/更新时间、评价、点赞、关联出场数和关联脚本数。

状态：草稿 → 待筛选 → 已选中／备选／淘汰。

支持新建、查看、编辑、复制、搜索、筛选、分页、评价、点赞、归档、恢复、修订和审计。

### 7.2 产品出场

字段：编号、标题、关联钩子、出场方式、出场时间、转场逻辑、产品卖点、画面描述、产品、标签、状态、创建者、负责人和评价。

一个钩子可以关联多个产品出场，使用真实外键。

### 7.3 完整脚本

字段：编号、标题、封面、关联钩子、关联产品出场、完整脚本、产品、人群、场景、标签、制作状态、创建者、负责人、截止日期、分镜、成品、投放、评价和复盘。

状态：草稿 → 待制作 → 制作中 → 已产出 → 已投放 → 已复盘。

详情继续沿用当前脚本弹窗和横向分镜视觉，并在同一窗口展示钩子、产品出场、脚本、封面、分镜、成品、投放、评价和复盘。

### 7.4 分镜

每个镜头：序号、名称、图片、画面描述、景别、时长、人物动作、台词/字幕、产品信息、备注。

支持添加、删除、拖拽/左右排序、换图、横向滚动、放大预览和无限镜头；保存后刷新仍存在。

### 7.5 成品视频

字段：名称、素材编号、产出日期、产出人员、源文件路径/云盘链接、预览链接、版本、备注。登记后首页产出数量自动更新。

## 8. 品牌内容模块

品牌内容以“项目”管理整套图片，页面复用当前完整脚本卡片和横向分镜展示。这五个分组是必须实现的业务子模块，不得简化为一个普通“类型”输入框。

页签：全部、品牌推广、产品内容、营销内容、渠道内容、售后内容。页签使用 V1 现有 `.tab` 样式，不重新设计。

### 8.1 品牌推广

必须包含：

- 品牌推广图
- 品牌 UGC 图
- 新品发布图

用于品牌形象、新品预热、发布和社交证明内容。项目卡片显示品牌、产品、用途、渠道、图片数量、负责人和状态。

### 8.2 产品内容

必须包含：

- 产品详情图
- 产品卖点图
- 产品场景图

用于独立站 PDP、广告落地页、社媒与详情说明。项目可记录卖点顺序、用户痛点、使用场景和图片在页面中的位置。

### 8.3 营销内容

必须包含：

- EDM 营销图
- 折扣营销图
- 节日／大促活动图

用于促销、闪购、黑五、节日活动等转化内容。项目可关联营销方案、优惠机制、活动时间和广告投放数据。

### 8.4 渠道内容

必须包含：

- 独立站 Banner
- SEO 文章配图

记录尺寸、使用页面、链接、SEO 主题/关键词、图片 Alt 文本和上线时间。

### 8.5 售后内容

必须包含：

- 使用教程图
- 产品保养图
- 常见问题图
- 故障排查图
- 配件说明图
- 售后流程图
- 客户关怀图

售后是客户生命周期内容，不是普通标签。每个售后项目需能关联客户生命周期节点，用于新用户欢迎、使用引导、问题解决、关怀、评价邀请、复购和老客召回。

### 8.6 品牌内容项目字段

所有分组共用：项目名称、内容分组、内容类型、品牌、产品、目标用户、使用渠道、负责人、制作状态、创建日期、截止日期、标签、项目说明、图片轨道、团队评价、版本记录、关联营销方案、关联客户生命周期节点。

状态：草稿 → 制作中 → 待审核 → 已通过 → 已发布；退回为待审核 → 待修改 → 制作中。

### 8.7 内容图片轨道

详情复用 V1 横向分镜板：上方/左侧横向图片轨道，右侧或下方当前图片详情。图片多时横向拖拽和滚动，不修改 V1 分镜表的视觉样式。

每张图片：图片 ID、角色、原图、预览、缩略图、使用位置、文案、提示词、产出平台、产出作者、上传者、上传时间、宽度、高度、文件大小、MIME、SHA-256、版本、审核状态、是否最终版、备注。

必须支持：添加、删除、更换、左右排序、放大预览、下载原图、审核通过、退回修改、设置最终版和版本记录。

## 9. 营销方案与客户生命周期

页面继续复用 V1 卡片、筛选栏、页签和详情弹窗。

### 9.1 方案中心

字段：名称、目标、用户、产品、利益点、优惠机制、渠道组合、内容清单、执行计划、目标数据、负责人、开始/结束日期、状态、标签、评价和复盘。

标签：新客、新品、折扣、大促、闪购、EDM、SEO、UGC、Meta、独立站、售后、客户关怀、复购。

状态：草稿 → 待执行 → 执行中 → 已结束 → 已复盘。

默认阶段：准备、预热、正式推广、最后召回、结束复盘。阶段包含时间、负责人、说明、关联内容和完成情况，可增删排序。

### 9.2 客户生命周期

节点：欢迎、使用引导、安装/激活、问题解决、客户关怀、评价邀请、复购提醒、配件推荐、老客召回。

每个节点包含触发时间、渠道、目标、关联品牌内容、负责人、状态和结果。

## 10. 广告数据

保留当前广告页面视觉，只替换数据源并扩展字段。广告记录按素材周期录入，不要求每日数据。

投放信息：对象类型、关联脚本/内容/方案、素材编号、批次、平台、币种、开始/结束日期、投放天数、状态。

状态：准备投放 → 正在投放 → 投放结束。

指标：Spend、Impressions、CPM、Link Clicks、CTR、LPV、Add to Cart、Initiate Checkout、Purchases、CVR、Revenue、CPA、ROAS、Frequency、Video Plays、3 秒观看率、50% 观看率。

公式：

- CPM = Spend / Impressions × 1000
- CTR = Link Clicks / Impressions × 100%
- CVR = Purchases / LPV × 100%
- CPA = Spend / Purchases
- ROAS = Revenue / Spend
- 投放天数 = 结束日期 - 开始日期 + 1

分母为零或字段缺失显示 `—`；缺失不能当零；不同币种不合计；跨筛选边界不按日拆分；环比使用完整等长周期；后端统一验证计算。

页面包含筛选、核心罗盘、周期记录、脚本/内容/方案排行、日周月环比、单对象分析和复盘。继续使用 V1 的蓝、粉、绿、紫、橙指标颜色。

## 11. 竞品洞察

复用 V1 卡片列表和详情弹窗。

类型：产品内容、独立站、营销策略、广告素材、EDM、SEO Blog。

字段：竞品、标题、类型、来源链接、截图/素材、产品、研究内容、可借鉴方向、已复刻内容、验证结果、标签、负责人、创建者、时间和评价。

## 12. 首页

保留 V1 首页布局、卡片和颜色，数据全部来自真实数据库。

模块：核心数据罗盘、当前待办、内容生产进度、最新品牌创意、最新品牌内容、执行中方案、投放中素材、售后完成情况和团队动态。

核心计数：钩子、出场、完整脚本、分镜、成品、品牌内容项目、执行中方案、投放中素材。

待办：待筛选、待制作、待审核、待修改、临期、缺素材生命周期节点、缺复盘投放。

## 13. 团队协作

保留并扩展现有评价、点赞和动态。

新增：评价回复、按对象统一关联、负责人、截止日期、我的待办、审核队列和内容变更通知。评价继续直接显示在卡片/详情中。

角色：

- 管理员：全部管理、广告数据、审核、归档恢复、用户权限、日志
- 操作者：创建和编辑自己内容、评价、删除自己评价、点赞；不能修改他人内容或广告数据
- 只读：查看；评价权限可配置；不能增删改归档

所有权限必须由后端校验。

## 14. 管理端

复用当前管理弹窗和表格视觉，包含：用户、角色权限、类型、标签、操作记录、归档、系统设置。

用户管理支持创建、资料、角色、重置密码、启用、禁用和二次确认删除。账号停用/删除不得破坏历史创建者信息。

日志字段：时间、操作者、模块、操作、对象、结果、IP、User-Agent；支持筛选和分页，重复登录合理聚合。

归档使用软删除，支持筛选、详情、原因、恢复和管理员二次确认永久删除。

## 16. V1 数据迁移

必须提供可重复、安全、可回滚的迁移工具：

1. 迁移前备份数据库。
2. 从 `state.entries` 读取旧记录。
3. 根据 kind 分别写入钩子、产品出场、完整脚本和品牌内容。
4. 分镜写入 `storyboard_shots`。
5. 视频写入 `produced_videos`。
6. 广告批次和周期写入广告表。
7. 评论、点赞、动态、修订、归档和操作日志保留。
8. 输出迁移前后数量对照报告。
9. 任一环节失败时回滚，不覆盖原数据库。

迁移完成前保留旧 API 兼容层；验证通过后才逐步切换页面数据源。

## 17. 图片存储和压缩

旧图片从 SQLite BLOB 迁移到：

```text
data/media/originals/
data/media/previews/
data/media/thumbnails/
```

上传流程：扩展名/MIME/真实解码 → 大小限制 → SHA-256 去重 → 保存未修改原图 → EXIF 修正 → WebP 预览/缩略图 → 元数据入库。

列表加载缩略图、详情加载预览、下载/放大加载原图。数据库禁止存 Base64。业务归档不删除源图，提供孤立文件检查和管理员清理工具。旧 `/media/{id}` 地址保持兼容，前端无需改变图片使用方式。

## 18. 安全

## 19. UI 验收规则

每个阶段都必须运行视觉回归测试。以下属于失败：

- 导航高度、位置、样式改变
- 页面最大宽度改变
- 卡片比例或按钮位置改变
- 弹窗布局被整体重画
- 分镜横向布局改变
- 广告数据罗盘配色改变
- 登录页刷新位移
- 表格文字被挤成异常多行
- Hover、圆角、阴影和字体出现明显差异

允许：在现有组件结构中增加必要页签、字段、卡片内容和新模块入口。
