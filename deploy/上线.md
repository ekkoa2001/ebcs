# 上线与恢复

本机默认仍使用 `data/sana_data.sqlite3`。页面、按钮和 `/media/{id}` 地址不变。Docker 启动后由 PostgreSQL、Redis 和 MinIO 接管，并把现有库导入空的 PostgreSQL。

## 域名

1. 只把 Nginx 的 443 暴露到公网。应用端口 8875 不映射到宿主机。
2. 把 `deploy/nginx.conf` 换成 `deploy/nginx-https.conf`，证书放到 `deploy/certs/fullchain.pem` 和 `privkey.pem`。
3. 在 `api` 环境变量设置 `EKKO_SECURE=1`，`EKKO_ALLOWED_HOSTS` 写成域名。登录来源会按 `https://域名` 校验，Cookie 带 Secure。
4. 上线前在管理端修改管理员密码。不要把现有密码写入仓库或文档。

对象存储在生产把 `S3_ENDPOINT` 改成阿里云 OSS 或 S3 的地址，保留 `S3_BUCKET`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`。浏览器仍请求 `/media/{id}`。

## 备份

备份 PostgreSQL 和对象存储。Redis 只放会话，不必备份。

```powershell
docker compose exec postgres pg_dump -U ekko ekko > ekko.sql
docker compose exec minio mc mirror local/ekko-media ./media-backup
```

SQLite 文件 `data/sana_data.sqlite3` 保留，作为导入前的回退副本。

## 恢复演练

1. `docker compose stop`
2. 用备份恢复 PostgreSQL 卷和对象存储。
3. `docker compose start`
4. 打开站点登录，并打开一张原来的图片，确认地址仍是 `/media/{id}`。

本机没有安装 Docker，编排文件已写好，尚未在这台电脑上执行 `docker compose up`。
